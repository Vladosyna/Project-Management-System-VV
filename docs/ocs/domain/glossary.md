# Glossary

| Term | Meaning | Source |
|---|---|---|
| **OCS** | Operations & Collaboration System — this platform (name not final) | D-01 |
| **Project ID** | `CLIENT-CC-CITY-NNN`, e.g. `NEINVER-ES-MAD-001`, `PMI-PT-LIS-001`. Primary business key of a project/site; used in mail subjects, DingTalk folder names, OA applications | SOP-DEL-02 §3 |
| **Standard L / S** | Per-site folder and process size. S: ≤ 20 sensors, mounting and connection only, no accompanying work. L: everything else. "When in doubt, L." Upgrade S→L allowed, never downgrade | SOP-DEL-02 §2 |
| **Handover package** | Project folder + Handover Card; **Full** (new clients/countries, installations, rollouts, POCs) or **Light** (add-points, replacements, supply-only on an accepted folder) | SOP-DEL-01 §3 |
| **Handover Card** | One-document summary Sales fills for every project, sections 1–11 (Annex B) | SOP-DEL-01 Annex B |
| **Intake review** | Delivery Director's check of the package → Accepted / Accepted with conditions (≤ 5 working days, non-blocking items only) / Returned | SOP-DEL-01 §8 |
| **Blocking items** | A1, A4, A6, C2, D1, F1 — can never be accepted as conditions | SOP-DEL-01 §8 |
| **Conditional Start** | Start before acceptance; only Hai Tao, in writing, naming missing items and a deadline ≤ 5 working days | SOP-DEL-01 §9 |
| **Intake Register** | Log of every submission: Project ID, date, decision, days to acceptance, returns; reviewed monthly with the Sales Lead | SOP-DEL-01 §11 |
| **CIP-L / CIP-S** | Client Implementation Pack, large / standard site. The client returns a **Site Information Card**. Same letter as the folder standard | SOP-DEL-04 |
| **Site Information Card** | The client's filled card (CIP-L or CIP-S) with photos and drawings. "No completed card, no installation date." | SOP-DEL-04 §1 |
| **Go / no-go** | Readiness decision the working day before installation; nobody travels to an unconfirmed site | SOP-DEL-04 §3 step 7 |
| **Site Register** | Programme-level list of sites with planned dates (client `00_General`) — in OCS this is the site list itself | SOP-DEL-02 §6 |
| **Folder numbers 00–11** | 00 Handover Card · 01 Commercial · 02 Site Information · 03 Site Visits · 04 Installation Plan · 05 Stock · 06 Installation · 07 Commissioning & Testing · 08 Client Handover · 09 Operation · 10 Project Management · 11 Internal Notes (restricted) · `_Archive`. Standard S uses the same numbers as file prefixes | SOP-DEL-02 §4–5 |
| **Action Record** | DingTalk Minutes template used for every meeting and site visit; Conference Theme starts with the Project ID | SOP-DEL-03 §5 |
| **Coverage X of Y** | Visit reporting rule: state coverage, never just "done" | SOP-DEL-03 §1 |
| **PMI gate template** | Client-specific template (not code): G1 Go/no-go (proposal + PO approved) · G2 Compliance approved (approvals, date agreed ≥ D−20, permits) · G3 Deployment ready (D−2 working days final check: IT/network, fixed IP per sensor, cables, access) · G4 Go-live approved (after calibration; dashboard access via the client's own systems) · G5 Closed / business as usual | PMI gates doc v2; D-12 |
| **D−2** | PMI-specific final check 2 working days before installation (renovation can finish just before installation) | PMI template |
| **Case** | One thread per problem/request from first message to fix; number `CS-nnnn` | D-03 |
| **Work item** | Internal task inside a case for exactly one team and one owner, with ETA | D-03 |
| **Internal ETA / committed date** | R&D estimate vs the date promised to the client by the delivery owner | D-06 |
| **Trust levels** | AI write permissions: automatic / proposal / human-only | D-07 |
| **G6 / G6S / G6 WiFi / B1** | Ceiling sensors (PoE / WiFi / island) | Product |
| **CBox** | Edge terminal analysing CCTV streams (e.g. queues) | Product |
| **V-store / OpenAPI v2** | Vionvision analytics platform and its API (footfall, online status) | Product |
| **AIoT** | Device management system — one of the device data sources to reconcile | Product |
| **DPIA / PIA / LPA / DPA** | Privacy impact assessment / local processing agreement / data processing agreement — compliance evidence on sites and clients | Compliance |
| **Data-saving mode** | Device setting that stops snapshot / hourly screenshot transmission; default once a project is stable | Engineering notes |
| **Partner A/B/C** | Client-facing labels for installation partners; real names are internal only | Standing rule |
| **Kingdee** | Company ERP (stock, invoices) — integrate, don't rebuild | D-14 |
| **OA** | DingTalk OA approvals; project applications carry the Project ID | SOP-DEL-01 |
