# 04 — Testing rules

## 1. Iron rules

1. **New behaviour → new test in the same PR.** No exceptions for "small" changes.
2. **Bug → failing test first** that reproduces it ("prove it"), then the fix.
3. **No completion claim without fresh evidence.** Run the command, read the exit code and output, paste the relevant part. "Should work" is not evidence.
4. **Tests assert the requirement, not the implementation.** Each test name reads as the acceptance criterion: `rejects intake when blocking item A4 is missing (SOP-DEL-01 §8)`. A test that mirrors the code line by line is rejected in review.
5. **No real client data** in tests. Factories and the anonymised seed only.

## 2. Pyramid

| Level | Share | Tool | What |
|---|---|---|---|
| Unit | ~80% | Vitest | Rules, evaluators, pure functions, command logic with fake repository |
| Integration | ~15% | Vitest + Testcontainers Postgres | Commands end-to-end through db with RLS on; repositories; adapters with fakes |
| E2E | ~5% | Playwright | Critical flows only (below) |

## 3. Mandatory suites

- **Permission matrix** — generated from the permission registry: every role × every command/query × own client / other client / internal. Runs on every PR. A new command without matrix entries fails CI.
- **RLS suite** — for every table with `client_id`: client actor sees only own client-visible rows; partner sees only assigned; staff cannot read restricted notes without permission.
- **Partner anonymity** — every client-facing query/projection: no partner real name, no internal staff R&D names where the spec says "team name".
- **SOP rule examples** — every rule config has a table of examples (input → expected decision, clause). Generated by `pnpm gen:rule`.
- **Audit** — every command produces exactly one audit record with actor, before/after, source.
- **Migrations** — up, down, up again on a seeded database.

## 4. Critical E2E flows (V1)

1. Sales submits Handover Card with A4 missing → Returned with clause; fixed → Accepted; Intake Register row updated with days to acceptance.
2. Accepted with conditions → condition deadline ≤ 5 working days → alert on expiry.
3. Create project Standard S, upgrade to L → folder mapping and Project ID unchanged.
4. Mail with `[CS-0412]` in subject arrives → attached to case; unknown mail → inbox suggestion; staff confirms.
5. Work item assigned → ETA set with reason → case ETA recalculated; ETA change without reason rejected.
6. Client-visible toggle: internal comment never appears in client projection.
7. Site without complete CIP card → installation date cannot be set (SOP-DEL-04 rule).
8. Alert R18 fires for work item without ETA after 2 working days (time-travel clock in tests).

## 5. Commands

| Command | Runs | When |
|---|---|---|
| `pnpm verify:quick` | typecheck + lint + unit for changed packages | Stop hook, before every commit |
| `pnpm verify` | typecheck + lint + unit + integration, all packages | Before PR |
| `pnpm e2e` | Playwright against local stack with seed | Before PR touching UI or flows |
| `pnpm test:matrix` | permission matrix + RLS suite | Every PR (CI) |

Integration tests and `pnpm e2e` start PostgreSQL with Testcontainers (Docker). To use an existing server instead, set `OCS_TEST_DATABASE_URL` (a role with CREATEDB and CREATEROLE; never a database with real data). Turbo runs tasks in strict env mode, so the variable reaches `test:integration` only because `turbo.json` lists it in `passThroughEnv`; `pnpm e2e` does not run through turbo and reads it directly.

## 6. Coverage

Changed lines ≥ 80% (CI, diff coverage). Rules and permissions modules ≥ 95%. Coverage never replaces rule 4.

## 7. Test data

- `packages/testing/factories`: `aClient()`, `aProject({standard:'S'})`, `aCase()`, `aWorkItem()`… with anonymised names (Client A, Partner A, Site 001).
- `packages/testing/seed`: a believable anonymised world built from the mockup structure: 3 clients (L-type, platform-heavy, S-type programme), 12 sites, 60 devices, 10 cases, 15 actions.
- A fake clock (`testing/clock`) for working-day and SLA logic; working calendars for CN and EU holidays.
